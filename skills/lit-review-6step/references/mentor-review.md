# 导师审查（MR）：全程防跑偏

## 为什么单独设一道

CR-S 审结构逻辑，HLA-S 审语言，两者都不回答一个问题：**这段内容还在回答用户最初的问题吗？**

跑偏通常不是一次发生的，而是每步扩一点：检索多搜了一个领域、taxonomy 多出一类、写作时顺手加了新问题、摘要承诺了正文没有的东西。导师审查只做一件事——对照主题契约，判断有没有偏题。

## 角色边界

- **只读**，不改稿、不重写；
- **不评价学术质量**（创新性、方法好坏、贡献大小）——那是审稿人和答辩委员会的事；
- **不替用户改题目**：发现题目本身变了，停下来问用户要不要更新契约；
- 每次结论必须有**证据**：哪一段、哪一行、哪条记录。

## 唯一锚点：主题契约

开工时写 `00_选题/主题契约.md`，至少包含：

- 题目；
- 一句 RQ；
- 范围：对象/场景、时间窗、语言、文献类型；
- **明确不做什么**（3–5 条）；
- 关键词（中英）；
- 成功标准：什么样的证据算回答了 RQ。

所有审查都对照这份契约。**契约变更必须显式**：用户确认 → 改契约 → 重跑受影响的阶段。不允许在写作阶段悄悄扩大范围。

## 每阶段只问三个问题

| 阶段 | 只问 | 典型跑偏 |
|---|---|---|
| S1 | 缺口是否支撑 RQ？模块是否都在 RQ 范围内？有没有偷换成另一个问题？ | 把“怎么做”写成“该不该做” |
| S2 | 概念块是否覆盖 RQ 的对象 + 机制 + 边界？有没有引入范围外概念？库和时间窗符合契约吗？ | 概念块多出一个不相干的领域 |
| S3 | 纳入文献是否服务于 RQ？E1 排除码有没有被滥用？候选表里有没有范围外主题？ | 因为“看起来相关”收进大量边缘文献 |
| S4 | 每行的 relevance 能否指回具体章节？提取字段是否围绕 RQ？ | 提取了一堆 RQ 用不上的变量 |
| S5 | 两套 taxonomy 是否回答 RQ？章节是否与 B 类一一对应？有没有新增未登记的研究问题？ | 第 3–5 章写成技术综述，忘了旧问题 |
| S6 | 终稿是否回答 RQ？摘要是否承诺了正文没有的内容？结论是否超出证据？ | 摘要里出现正文没讨论的“未来方向” |

## 三级判定

| 判定 | 含义 | 处理 |
|---|---|---|
| **PASS** | 仍在契约范围内 | 进入下一阶段 |
| **WARN** | 轻微扩展，可继续 | 记录到 `00_选题/导师审查.md`，下一阶段开头复核 |
| **BLOCK** | 已偏离，写了也白写 | 退回上一阶段，不能靠后面的写作补 |

WARN 不阻断，但必须留下痕迹；同一主题连续两次 WARN，升级为 BLOCK。

## 输出格式

```markdown
## 导师审查｜S3｜2026-11-11
| # | 检查项 | 证据 | 判定 | 说明 |
|---|---|---|---|---|
| 1 | 研究对象 | 候选表 62% 是新闻推荐 | WARN | 契约写的是电商；要么补 E1 排除，要么扩大契约 |
| 2 | RQ 机制 | 全部纳入文献都在比较 GNN 结构 | PASS | 与 RQ 的信息传播机制一致 |
结论：WARN（继续，但下一阶段复核范围）
契约变更建议：无 / 把“新闻推荐”纳入范围（需用户确认）
```

## 频率

- 每个阶段门禁前一次；
- S5 每章一次（可与 CR-S 同批跑）；
- S6 终稿一次；
- 用户中途改题目时，立即一次。

## 与 CR-S、HLA-S 的分工

| 模型 | 管什么 | 不管什么 |
|---|---|---|
| **导师审查 MR** | 是否还在回答用户的问题 | 结构是否完整、语言是否通顺 |
| **CR-S** | 七节结构、章节映射、论证链、防御性语言 | 主题是否偏了 |
| **HLA-S** | 章际承接、段落节奏、术语一致 | 观点与范围 |

顺序：**MR → CR-S → HLA-S**。先确认没跑题，再谈结构和语言。
