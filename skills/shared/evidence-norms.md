# 证据与语言规范

三个 skill 共用。写提纲、正文、摘要时都适用。**冲突时以本文为准。**

## 一、四条语言规范

| 规范 | 要求 |
|---|---|
| 默认中文 | 解释、正文、提纲、摘要用中文 |
| 保留英文 | 论文标题、变量名、模型名、软件命令、参考文献条目保持原文，不翻译 |
| 不编造 | 不虚构 DOI、作者、期刊、页码、数据、实验结论 |
| 标注来源 | 定量结论、数据集、图表必须带来源标签 |

## 二、四级来源标签

| 标签 | 含义 | 能否进正文 |
|---|---|---|
| `用户提供` | 用户给的文献、数据、笔记 | 能，句末标“（用户提供）” |
| `已核验` | 在 `01_检索/候选表.csv` 且 `included=1`，读过原文或摘要 | 能，正常引用 |
| `未核验` | 有出处，但没核对原文 | 能，但标“（未核验）”，并进 to-verify 清单 |
| `待核` | 记不清、拿不准、只记得大意 | **不能写成断言**，只能进 to-verify 清单 |

## 三、写作时的三条硬检查

1. **引用可回溯**：每一个 `[作者, 年]` 都要能在候选表里找到 `included=1` 的行；找不到就降级为“待核”。
2. **数字有出处**：样本量、准确率、年份窗、文献数，都要能指到具体文献或检索日志。
3. **不确定就明说**：写“未查到”，不要用“研究表明”“大量文献指出”兜底。

## 四、交付前附 to-verify 清单

每次交付末尾加一段：

```markdown
## 待核
- [ ] 某某结论（只在摘要里见过，未读全文）
- [ ] 某某数字（来源待查）
```

清单不为空时，正文对应位置必须标“待核”。清单为空也要写“无”。

## 五、语言细节

- 不用“随着……的快速发展”“近年来受到广泛关注”开头。
- 不用“众所周知”“显而易见”这类无依据的断言。
- 引用格式全文统一（GB/T 7714 或 APA），不在同一篇里混用。
- 中英混排：英文术语与中文之间留空格；英文术语不硬译（如 transformer 不译“变换器”）。

## 六、适用范围

- `lit-review-6step`：S3 建候选表时打标签，S5/S6 引用前核对。
- `survey-writing`：写正文时逐段检查引用与数字。
- `survey-abstract`：摘要里的每个数字都要能回到正文。
