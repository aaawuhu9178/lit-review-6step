# 综述写作：先建地图，再动笔

综述是一篇有论点的学术论文，不是文献的中立堆叠。它必须交付三样东西：一张可导航的地图、一套能解释现有工作的分类坐标、一个由地图自然长出的研究议程。

**证据与语言以 `../shared/evidence-norms.md` 为准**：引用必须能回溯到候选表，数字必须有出处，拿不准写“待核”。

**硬规则：taxonomy 没有填满、核心论点不能用一句话说清之前，不写正文。** 边写边分类，结构一定漂移。

## 先判断用户在哪一步

| 用户请求 | 先交付 | 重点读 |
|---|---|---|
| 只有题目，问怎么写 | 物种选择 + 一句话论点 | §1–2 |
| 已有题目，要搭骨架 | taxonomy 草图 + 五节大纲 | §3–4 |
| 要写摘要 | 加载 `survey-abstract` 的五段式 | 该技能 |
| 要写引言 | 引言矛盾链 + 五节骨架 | §4 |
| 要规划图 | 五类图的角色清单 + 图序 | §5 |
| 想让文章上一个档次 | 差异化清单 + 缺口分析 | §6 |
| 改稿/审稿式检查 | 死法诊断 + 优先级 | §7 |
| 要审结构逻辑、跨章连贯 | CR-S / HLA-S 报告 | §8 + `references/review-and-alignment.md` |

只问缺失且会改变方案的信息：主题、目标读者、venue/篇幅、交稿时间、现有文献库或角度。用户没给，就明确假设后继续，不要用问题卡住交付。

## 1. 先选「物种」

| 物种 | 适用时机 | 主线 | 主要风险 |
|---|---|---|---|
| 叙事型 | 领域尚在成型；读者是跨学科外行 | 原理与演进；图少而精，用 Box 讲基础概念；回答「为什么有效」 | 需要权威/约稿背书；新手写容易变成科普 |
| 分类型 | 方法数量爆炸；社区急需一张地图 | 通用 pipeline → 所有方法归入各阶段 | taxonomy 立不住，全文就塌 |
| 问题导向型 | 「方法 X 应用到领域 Y」的交叉地带 | 按领域自身问题结构（如信息类型 × 任务）组织；每类做「挑战 → 现有工作如何应对」 | 对领域问题的理解不够深 |
| 全景型 | 新领域狂飙突进、三个月一换代 | 历史演进 → 架构 → 资源/数据集 → 行业应用 → 开放挑战 | 覆盖广但无深度；检索截止日期一过就陈旧 |

选择规则：

- **新手优先问题导向型。** 结构是领域自带的，不需要发明分类维度，失败率最低。
- 只有能持续维护一套自洽 taxonomy 时，才选分类型；只有拿到足够授权、且领域确实需要定义之作时，才选叙事型。
- 混合型可以借模块，但必须有一个**主导物种**；不要把四种写法平均混合。
- 选完物种，先写一句「本文属于 ___ 型，因为读者是 ___，领域当前缺的是 ___」。写不出，说明还没选好。

## 2. 锁死范围与论点

先填一个 scope contract，再谈写作：

- **检索**：数据库（Web of Science / Scopus / Google Scholar / arXiv / ACL / DBLP 等）、关键词与布尔式、时间窗、检索日期。
- **纳入/排除**：语言、venue/peer-review 要求、任务/模态边界、最小实验标准。
- **种子集**：5–10 篇奠基作 + 5–10 篇最新代表作；再做前向/后向滚雪球。
- **数量**：记录检索命中、去重、筛读、最终纳入的数量，供「覆盖范围」声明使用。

再写**一句话论点**：

> 现有工作可以沿 ___ 这条轴组织；沿这条轴看，真正的空白是 ___，因为 ___。

这句话是全文的合同。它必须能同时解释：为什么需要这篇综述、taxonomy 为什么长这样、挑战章节为什么是这些挑战。

## 3. 用 taxonomy 做心脏

综述和普通论文最本质的区别在这里。先回答四个设计问题：

1. **按什么维度分？** 常见四轴：方法机制（谱方法 vs 空间方法）、信息类型（有无 side information）、任务类型（通用推荐 vs 序列推荐 vs 社交增强）、学习范式（监督 vs 自监督）。**一篇文内只用一套主维度，不混轴。**
2. **要不要双维交叉？** 双维（如「信息类型 × 任务」）天然产生空白格；空格就是未来方向，但要先验证是真空白，不是你没检索到。
3. **要不要自创坐标系？** 如「输入 → 表示 → 消息传递 → 输出」的通用 pipeline。自创坐标系是最高加分项，也是最大风险项：必须能用更少的例外解释更多的论文。
4. **每个叶子节点给什么？** 标配是「一篇代表作 + 一张对比表（方法 × 关键特性）+ 一句取舍判断」，不是方法名罗列。

执行顺序不可颠倒：

1. 画 taxonomy 总图；
2. 建证据表：论文、年份、venue、方法族、假设、优势、局限、数据集、代码；
3. 把论文填进格子；
4. 做**十篇盲测**：随机抽 10 篇，若超过 2 篇放不进去或跨格，改 taxonomy；
5. 格子填满后，才写正文。

分类质量的四个检查：互斥（不重）、穷尽（不漏）、稳定（换一批论文不崩）、有解释力（能推出挑战与空白）。做不到，不要用「其他」兜底一个大杂烩类别。

## 4. 五节骨架与章节写法

### 4.1 五节骨架

引言：定义 + 问题张力 + 缺口 + 贡献；预备知识；主体分类（taxonomy 总图 → 每类 → 对比表 → 取舍）；应用；挑战与展望。

预备知识用几张领域直觉图把前提焊死；综合型综述在引言放一张本文结构图。

### 4.2 引言：六段漏斗

1. **大背景 ~15%**：任务/技术的社会或科学价值，1–2 段。
2. **技术主线 ~20%**：核心方法/对象演进，点关键工作，过渡到综述对象。
3. **挑战 ~15%**：2–4 个悬而未决的问题，用 (i)(ii)(iii)；taxonomy 必须回链这些挑战。
4. **缺口 ~15%**：`existing surveys either…or…; none provides…` / `To the best of our knowledge, this is the first survey to…` / `Unlike previous surveys [n], we…`。这是综述引言的身份标志。
5. **本文工作 ~25%**：`In this survey, we…` + 3–5 条 bullet 贡献，动词开头，与摘要逐条对应。
6. **组织结构 ~10%**：`Section 2… Section 3…`，逐段一句。

贡献动词：`provide / propose / summarize / release / discuss`。时态：领域事实现在时，他人工作现在完成/过去时，本文现在时。摘要→引言：钩子扩成①②，taxonomy 拆成④+⑤，challenges 扩成③。

### 4.3 分类章节

四轴：输入/数据 × 任务；方法机制；pipeline 阶段；生命周期。分类轴必须能追溯到引言的挑战段。

每节四件套：**操作性定义 → 代表作按时间/思想演进 → “While effective…” 批判收尾 → 对比表**（方法 × 数据集 × 指标 × 特性，全表统一记号）。

章节树：背景/预备 → taxonomy 总览 → 各类别逐节 → 数据集与指标 → 应用/benchmark → 挑战 → 结论。

SLR 式综述加「检索方法」：数据库、关键词、纳入/排除标准、PRISMA 流程图；报告初筛数、纳入数、时间窗、RQ 数。

### 4.4 结论：三段

1. **总结 ~1/3**：回收 taxonomy 与资源贡献，现在完成时，不引新文献。
2. **挑战 ~1/3**：编号；每个 = 陈述 + 为何难 + 现有为何不够。
3. **方向 ~1/3**：与挑战一一对应，用 `will / may / deserve further investigation`；不写新论断；结尾留领域愿景。

最规范：挑战与方向合并成一节，每个小节先摆难题、后给方向。

摘要单独拆为 `survey-abstract` 技能。写摘要、改摘要、检查摘要时加载它；本技能只负责正文结构、taxonomy、图表和审计。摘要最后写，但要用它当全文合同：摘要承诺的板块，正文必须一一兑现。

## 5. 图是论证，不是装饰

顶刊综述的图通常分五种角色：

| 图种 | 任务 | 判断标准 |
|---|---|---|
| 领域直觉图 | 让外行看懂「为什么是这个问题」 | 不看正文也能建立正确直觉 |
| 通用框架图 | 成为全篇的分类坐标系 | 后文所有方法都能落在它的阶段上 |
| Taxonomy 总图 | 一图公示分类体系 | 读者靠它导航全篇 |
| 每类框架图 | 每类一张 overall framework | 类内差异一眼可见 |
| 本文结构图 | 展示综述自己的 architecture | 引言里就能看懂全文路线 |

预算：中等篇幅 6–10 张图；叙事型可少到 1–2 张核心原理图。每张图的 caption 写**结论句**，不写「某某示意图」。一张图如果不能用一句话说清它支撑什么论点，就删掉。

三张示例图及读图要点见 `references/figure-gallery.md`：通用设计流水线、taxonomy 总图、本文结构图。它们只作结构参考，复用前核对版权；最稳妥是重绘并注明「改编自 ___」。

## 6. 拉开档次的六件事

1. **挑战—对策式分析，而非罗列。** 每节回答「这类数据难在哪、现有工作怎么应对、应对得够不够」，不是「A 做了 X，B 做了 Y」。
2. **开放问题要具体。** 用「当前在 ___ 条件下做不到 ___，瓶颈是 ___，可能的突破口是 ___，验证方式是 ___」；删掉「缺乏统一评价标准」这类放之四海皆准的空话，除非你说清哪个任务、哪个指标、为什么现有 benchmark 不够。
3. **挂开源仓库。** 收录代表论文、开源实现、数据集；写清维护方式与许可证。仓库要把综述变成领域基础设施，而不是一次性附录。
4. **对比表是肌肉。** 每个类别一张「方法 × 特性」矩阵，列假设、输入、核心机制、数据集、指标、代码；读者查表就能定位文献。
5. **声明覆盖范围。** 敢写 comprehensive，就交代检索策略；做不到，就诚实写 selective review 并给出边界。
6. **把 taxonomy 的增量写进贡献列表。** 写摘要时用 `survey-abstract` 把这一增量显性主张；沿用别人分类而不做增量，是审稿人最先攻击的点。

## 7. 死法诊断与质量门

按出现频率排序：

| 死法 | 症状 | 修法 |
|---|---|---|
| 文献堆 | 没有 taxonomy，正文是「某某等人做了……」的接力 | 停下来建轴、填格子，再重写 |
| 照抄分类 | 沿用已有维度，没有增量 | 加一个能解释新现象的维度，或重新划界并论证 |
| 只引近三年 | 漏掉 transformer、BERT 这类奠基作 | 种子集补经典，做后向滚雪球 |
| 挑战章节空话 | 「缺乏统一标准」「仍需进一步研究」 | 改成可检验的具体瓶颈与验证方式 |
| 摘要写成目录 | 只有「首先/然后/最后」，没有观点 | 用 `survey-abstract` 重写：钩子 → 定位 → 框架（分类轴 + 数字）→ 证据 → 挑战/机会 |

三道质量门：

- **Gate A（动笔前）**：物种已选；一句话论点成立；scope contract 已填；taxonomy 通过十篇盲测。
- **Gate B（写正文前）**：摘要已按 `survey-abstract` 检查；五节大纲齐全；图表计划能支撑每一节的论点；贡献列表可逐条兑现。
- **Gate C（投稿前）**：每个叶子有代表作 + 对比表；每节有分析而非罗列；开放问题具体；覆盖范围有交代；奠基文献没漏；图 6–10 张且每张有结论句；仓库可访问；每章都有 CR-S / HLA-S 记录（见 §8）。

审稿人三问，全文必须答上：**你的论点和别人的综述有什么不同？你的分类为什么比现有分类好？你说「开放」，到底什么还开着？**

## 8. 两个辅助模型：CR-S 与 HLA-S

写和审分开。写作模型会替自己的句子辩护，所以另设两个**只读**模型：

| 模型 | 管什么 | 不管什么 |
|---|---|---|
| **CR-S 结构-逻辑审查** | 七节结构、B 类数与章数、章节映射、论证链、防御性语言 | 字号、标点、著录格式、单句用词偏好 |
| **HLA-S 人类语言对齐** | 章际承接、段落节奏、术语一致、去 AI 腔 | 观点、事实、数据、结论、引用归属 |

什么时候跑：

1. 每写完一章 → CR-S → HLA-S；
2. 全文初稿完成 → CR-S（全文）→ HLA-S（通读）；
3. 摘要定稿前 → CR-S（摘要）；
4. 每轮改完 → CR-S 复审。

顺序不能反：先定结构逻辑，再顺语言；反了会把结构问题藏进漂亮句子里。

CR-S 只报 P0（结构断裂、结论无依据、前后矛盾）和 P1（衔接生硬、重复、防御性、术语漂移），**P2 措辞偏好不报**；每节最多 5 条，没问题写"通过"。HLA-S 逐段给"原文 → 改写"，只改表达，不改作者判断的强弱。

完整规则、词表、输出模板和记录方式见 `references/review-and-alignment.md`；每次结果写进 `05_成稿/审校记录.md`。

## 9. 交付方式

- **用户说「写一篇综述」**：先交付一页蓝图（物种、论点、scope、taxonomy 草图、五节大纲、图表计划），确认后再逐节写。用户要直接出稿，也先在开头用 5–10 行给出蓝图与假设，再写。
- **用户说「改稿」**：先按 §7 做诊断，按严重度排序；先动结构和论点，再润色句子。不要静默改变原作者的 claim。
- **引用纪律**：不编造论文、作者、DOI、实验结果；没读过的文献标「待核验」；示例标签只作结构参考，正式引用前核对原文。
- **语言**：默认跟随用户语言；中文学术写作避免翻译腔和营销词。

需要更细的范文拆解、逐节写法、taxonomy 工作坊和审稿问题清单，读 `references/playbook.md`；需要看图，读 `references/figure-gallery.md`；要审结构或连贯性，读 `references/review-and-alignment.md`；写摘要，加载 `survey-abstract`。需要直接开工，复制 `assets/review-blueprint.md` 填完再写。
